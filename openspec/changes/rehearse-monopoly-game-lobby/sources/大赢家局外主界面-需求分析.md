---

> **⚠️ 前置：三条决定本文档形态的工程事实（先读）**
> 1. **大厅是全新模块，零存量代码。** `Runtime/Script/UI/` 下只有 `Game/`、`Settlement/`、`Shared/` 三个空 `.gitkeep`，**没有 Lobby**。本仓实现过的业务仅限于 Root 空壳场景（`MonopolyRoot.unity`，纯黑竖屏 1080×2160），掷骰/移动/购买/胜负一律未实现。因此本文档所有 P0 项都是「从零建」。
> 2. **不能复用 `cn.jj.tkhall`。** 共享大厅模块（斗地主 / JJ 麻将 / JJ 斗地主在用，含 `HallLobby`/`HallMyinfo`/`HallMerch`/`Theme`/`TabWidget`，版本 4.0.0）确实存在，但本仓 `package.json` 的 `dependencies` / `moduleDependencies` **都没有 `cn.jj.tkhall`**。按项目规则「跨模块一律走 bifrost 的 `IXxx`，禁止引用其它模块的实现类型」，**tkhall 只能作 UI 与交互的参考实现，不能直接调用**。要做复用须单独决策（见 §7.2 方案 B）。
> 3. **本仓没有服务端代码。** 好友、聊天、排行榜、历史、充值订单、局内流水**全部需要服务端**，而 `Runtime/Script/Network/` 只有空的 Sender/Handler 预留位，`.proto` 生成物为空。服务端归属未定 → **RX1（🔴，全部局外功能的总阻塞）**。

|--------|--------|----------|

> **`客户端 + 服务器` 这类组合写法表示两侧都要出人**，不是一个人干两份活。排期时必须拆成两条工单。

| **座驾** | 纯外观载具，**不改任何数值**。局内全程驾驶状态、无下车动作，且**只能在局外更换**（QCX7） |
