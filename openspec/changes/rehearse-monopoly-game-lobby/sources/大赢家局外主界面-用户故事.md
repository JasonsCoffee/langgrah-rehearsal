# 大赢家 · 局外主界面 用户故事

> **文档版本**: v1.0
> **生成日期**: 2026-11-11
> **依据文档**: `大赢家局外主界面-需求分析.md` v1.0（本目录）
> **源文档**: `大赢家主界面策划案.docx` + `11-10 大厅系统设计-听记原文.txt` + `11-10 大厅系统设计-会议纪要.md` + 局内文档 `../InGame/大赢家局内玩法-用户故事.md` v2.3（场次 / 货币 / 排名 / 放弃局口径的唯一来源）
> **规模**: 13 个史诗（S1~S13）+ NFR，共 **119 个用户故事**，覆盖需求分析的全部 **143 个功能项**
> **状态**: v1.0 初版。**P0 27 / P1 27 / P2 31 / P3 33 / 本期不做 1**

> **⚠️ 编号前缀**：史诗 `S{X}` 与需求分析模块 `L{X}` 一一对应，故事 ID 为 **`US-L{X}-{YY}`**（注意中间是 `L` 不是 `M`）。局内文档用 `US-M{X}-{YY}`。**跨文档引用必须带前缀**，否则 `US-L1-01` 与 `US-M1-01` 极易混淆。
> **⚠️ 与局内的边界**：本文件**只写局外**。凡涉及局内结算的（流水逐笔、放弃局利润、名次），验收标准一律引用局内故事，不在此重复定义——**只在「数据从哪里来」这一层断言，不重写局内规则**。

**一句话背景**：大赢家的局外主界面是玩家在 JJ 大厅点图标后进入自己的首页——一个带 3D 角色的街道场景，上面叠货币栏、场次轮播、「开始」按钮，右上角汉堡菜单展开好友 / 排行榜 / 历史 / 商城 / 设置 / 聊天。**它必须承担三件事**：让玩家有钱进来（货币栏 + 充值）、凑得出 24 人（匹配 + 组队）、有理由再来（形象 + 排行榜）。本文件把需求分析的 143 个功能项拆成可独立领取、可独立验收的开发单元。

### 结构说明

- 史诗 `S{X}` 与需求分析模块 `L{X}` **一一对应**（S1↔L1 … S13↔L13），非功能需求单列 `NFR`。
- 故事 ID 格式 `US-L{X}-{YY}`；非功能需求用 `US-NFR-{YY}`。
- 每个故事带 **「覆盖功能项」** 字段，指回需求分析的 `L{X}-{NN}`。**功能项与故事不是严格 1:1**——同一交付单元内耦合过紧的条目（如「使用中标识」与「默认选中当前形象」）合并为一个故事，但**每个功能项必须且只能被一个故事覆盖**（覆盖率由脚本校验，见附录 D）。
- **「执行端」只写需求分析认可的四类**：客户端 / 服务器 / 平台 / 策划表 / 美术。`客户端 + 服务器` 表示两侧都要出人，排期须拆两张工单。

## S1: 主界面框架与场景 (L1)

### US-L1-01: 从 JJ 大厅加载主界面并返回

**作为** 玩家
**我希望** 在 JJ 大厅点游戏图标后进入大赢家的主界面，并能随时返回大厅
**以便** 进出游戏符合 JJ 平台其它游戏的肌肉记忆

**优先级**: P0
**状态**: ✅ 已确认
**执行端**: 客户端
**覆盖功能项**: L1-1, L1-3
**验收标准**:
- [ ] 从 JJ 大厅点图标 → loading → 进入**主界面场景**（是一个场景，不是纯 UI 叠层；场景内展示 3D 角色模型）
- [ ] 左上角返回按钮点击后回到**进入前的 JJ 大厅**，不做二次确认
- [ ] 从局内返回主界面走同一入口，不出现「两次 loading」

**依赖**: US-L1-02, US-NFR-02
**阻塞于**: —

**作为** 玩家
**我希望** 主界面有一个能站人的街道背景和中央角色展示区
**以便** 我能看到自己买的皮肤和座驾长什么样

**优先级**: P0
**状态**: ⏸ 搁置
**执行端**: 美术 + 客户端
**覆盖功能项**: L1-2
**验收标准**:
- [ ] 街道风格背景 + 中央角色模型展示区（视觉稿占屏幕中部约 55%）
- [ ] 角色默认循环播放**待机动作**，切场景/切界面回来不丢状态
- [ ] **P0 阶段允许用占位场景跑通链路**，不等美术定稿（见需求分析 §7.2 方案 B）

**依赖**: —

## S2: 货币栏 (L2)

### US-L2-01: 货币余额展示与格式化

**作为** 玩家
**我希望** 在顶部货币栏看到我的勾勾金币和元宝余额，且数字一眼能读懂
**以便** 判断自己进得起哪个场次、买不买得起一件皮肤

**优先级**: P0
**状态**: ✅ 已确认
**执行端**: 客户端 + 平台
**覆盖功能项**: L2-1, L2-2, L2-3
**验收标准**:
- [ ] 显示玩家账户 **勾勾金币** 与 **元宝** 总数，数据取自平台，游戏侧不落库
- [ ] 格式化三段式：**不足 1 万**按实际数量显示；**1 万 ~ 10 万**用单位「万」、`实际/10000` **向下取整保留 1 位小数**（`55999 → 5.5万`）；**10 万以上** `实际/10000` **向下取整只保留整数**（`129999 → 12万`）
- [ ] **元宝的格式化规则与金币完全相同**，共用一个格式化函数，禁止两套实现
- [ ] 边界值逐条测：`9999 / 10000 / 19999 / 99999 / 100000 / 129999 / 0`

**依赖**: —
**阻塞于**: —
**待定数值**: 无（规则已闭合）

> **⚠️ 向下取整是刻意的**：55999 显示 `5.5万` 而不是 `5.6万`，这是策划案明写的。若改成四舍五入，玩家会看到「5.6万」却付不出 56000，产生客诉。

## S3: 玩家形象 (L3)

> **⚠️ 全模块 P3**（用户裁决）。理由：**默认形象即可开局**，形象系统不影响「能不能玩」，只影响「愿不愿意花钱」。S3 与 S7 商城、S12 充值同属商业化链条，实际排期应整块推进。

### US-L3-01: 形象设置入口与页签

**作为** 玩家
**我希望** 点中央角色就打开形象设置界面，默认停在皮肤页签
**以便** 换装是「一点就到」的，不用在菜单里找

**优先级**: P3
**状态**: ✅ 已确认
**执行端**: 客户端
**覆盖功能项**: L3-1, L3-2
**验收标准**:
- [ ] **点击中央角色模型展示区任意位置**打开形象设置界面（热区边界见 QX13）
- [ ] 进入后**默认选中「皮肤设置」页签**；另有「座驾」页签
- [ ] 从商城「去获得 / 立刻换装」进入时**可指定页签与目标项**（见 US-L7-05 / US-L7-07）

**依赖**: US-L1-02
**阻塞于**: —
**待定数值**: 角色展示区点击热区边界 —— QX13
